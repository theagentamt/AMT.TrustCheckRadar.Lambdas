## Reproduced limitation and fix decision

An expired retained paid source followed by a fully verified independent root is rejected by the handoff head guard in synthetic tests. The writer independently rejects a different `subscriptionDigest` or backwards source revision as `STORE_AUTHORITY_MIGRATION_REQUIRED`, publicly mapped to reconciliation503. That second guard is not a producer of the observed transition409. Deleting only the handoff guard would merely expose the writer rejection, and bypassing both without an atomic migration policy risks usage resets, overlap or ownership mistakes.

The limitation is therefore recorded under existing backend scope, not relabeled as a uniquely diagnosed live defect. No grant behavior is changed. An explicit normal-repurchase implementation would need a verified atomic root-transition design across both layers, preserving previous source/period and global usage, owner/deletion/device fences, exact CAS, idempotency and historical spending. It needs negative overlap, cross-owner, stale-provider, deletion, concurrency, replay and lost-commit tests; changing an error label or ignoring expired history is insufficient.

The smallest missing evidence is a finite internal predicate at the original rejection site. A later source candidate can attach only a fixed enum and emit it under Dev/exact-route/existing gates, with the same public response and no token, account/order/request ID, provider field values, raw exception text, extra provider read or re-evaluation. This checkpoint does not implement or deploy that candidate, replay an existing proof, call an app endpoint, activate lifecycle or authorize another transaction. Historical predicate attribution remains unavailable from the retained public diagnostic.
