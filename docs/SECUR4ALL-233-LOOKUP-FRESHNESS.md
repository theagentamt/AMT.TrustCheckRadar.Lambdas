# SECUR4ALL-233: bounded Lookup freshness correction

This increment preserves Google's original Lookup `expireTime` through private assessment, governed URL/message receipts, public presentation and historical export. It does not complete all SEC233 acceptance criteria. No provider calls, deployment, paid recheck, new cache, retention extension, or general admission were performed during source qualification.

- [Feedback compatibility supplement](../contracts/result-feedback/assessment-compatibility-2026-09-28/README.md): the same feedback request/response version and policy accept the two additional original assessment reference versions. No new submission content or provider request. Original receipt version is checked and conditionally guarded. Frozen prior contract files are unchanged.

URL preparation binds its version inside the original payload HMAC and records it on preparation/receipt. Candidate1 new preparation/submission is rejected before grant refresh, reservation or provider work. Existing candidate1 original-proof reconciliation remains supported but unverifiable Google findings are unavailable. New/old proofs cannot reinterpret one another. Settlement also validates private schema against the bound receipt version.

Later expiry is a presentation change only: it never rewrites the settled receipt, original evidence, chargedChecks, counters or original operation identity. Expired replay uses do_not_retry even if a different current device/subscription gate blocks a new check. An expiry detected before the first settlement transaction releases the original reservation uncharged; it does not repeat the provider invocation. The network transaction boundary cannot attest the provider's clock; it checks local precise wall time immediately before dispatch, with no invented future validity allowance.

Legacy message reconciliation removes unverifiable Google basis. If a conservative result cannot fit the old charged-result schema, the response omits the assessment while retaining accounting; the historical original remains exportable. Modern clients must also expire displayed current evidence at its original deadline and handle clock rollback conservatively. Backend expiry is not sufficient for a screen left open.

## Still open / release handoff

This correction must not be described as completing Google's cache recommendation/obligation. Any URL-bearing cache design needs its own approved retention, ownership/deletion/export and cost/recheck treatment. No automatic paid refresh policy is introduced.

General consumer admission remains closed. Coordinated backend/client source pinning, exact artifact review, any later authorized Dev deployment qualification, and Android freshness behavior are prerequisites to activation. Manual/physical release validation belongs in the linked release-test handoff; this source increment does not claim it ran. Root owns story status and infrastructure evidence. The immutable old contracts and existing cleanup/export proofs remain historical evidence, not new provider-live evidence.
